# Oracle 21c (XE) Alongside 23ai Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish `sakiladb/oracle:21` (Oracle 21c XE, amd64) from the same `master` and tag-driven
release as `:23`, with one shared set of SQL files and a CI smoke test for every version.

**Architecture:** The Dockerfile has one pinned base stage per Oracle major, selected by
`ARG ORACLE_MAJOR`. A small script works out which versions and platforms a CI run builds (tag →
one version; everything else → all versions), and the workflow fans that out into a matrix. Every
build is run and queried by `smoke-test.sh` (counts, BLOB, golden view hashes) before anything is
pushed.

**Tech Stack:** Docker/BuildKit, gvenzl Oracle images, SQL\*Plus, Python 3 standard library
(`unittest`), bash, `jq`, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-17-oracle-21c-design.md`. The spike it cites is on branch
`spike/21c-xe` (`git diff master spike/21c-xe`). It's a throwaway, but its code shows that each
change works on both versions.

## Global Constraints

- Base pins, exactly: `gvenzl/oracle-free:23.26.2-slim-faststart` (23) and
  `gvenzl/oracle-xe:21.3.0-slim-faststart` (21).
- Known versions: `21`, `23`. `LATEST_VERSION` = `23`. Platforms: 23 → `linux/amd64` on
  `ubuntu-latest` + `linux/arm64` on `ubuntu-24.04-arm`; 21 → `linux/amd64` on `ubuntu-latest` only.
- Sakila contract on every image: 16 tables, 7 views; `actor` 200, `film` 1000, `rental` 16044,
  `payment` 16049; `staff.picture` length 36365 on `staff_id = 1`, NULL on `staff_id = 2`.
- Credentials: PDB `SAKILA`, user `sakila`, password `p_ssW0rd`.
- Data file: one `INSERT INTO <table> VALUES (…);` per row (46,273 total); BLOB chunks of 2000 hex
  chars (1000 bytes), 37 `WRITEAPPEND`s; no line in any generated SQL over 2999 chars.
- Only a **tag push** publishes. `:latest` only for `LATEST_VERSION`.
- Commits and PRs: no AI attribution of any kind (no trailers, footers or session links), per the
  maintainer's global instructions.
- Don't push tags, publish releases or delete remote branches without asking the maintainer first.

## Review Focus

1. **Unknown or malformed version** (`workflow_dispatch` input `22` or `21;rm -rf /`, tag
   `v22.0.0`): the run fails fast with a clear `::error::` before any build starts. Pinned in Task 4's
   `resolve-version_test.sh`.
2. **Tag order and `:latest`**: pushing `v21.0.0` after `v23.0.8` must not move `:latest`, and
   `v23.x.y` must still set it. Pinned by Task 4's `is_latest` cases, and checked against the
   registry after release (Task 6).
3. **A container that never becomes healthy, or exits early**: `smoke-test.sh` fails within its
   timeout with diagnostics, instead of hanging the job. Pinned in Task 3 (run against an image with
   no Oracle in it).
4. **A generator change without regenerating the data file**: CI fails. Pinned by Task 1's
   `test_committed_data_file_is_current`, which runs in CI (Task 4).
5. **A plain local `docker build .` with no build arg**: still produces 23. An unknown
   `ORACLE_MAJOR` fails with a clear error. Pinned in Task 2.

**Interfaces:**
- Produces: `./smoke-test.sh [--update-hashes] IMAGE`, which exits 0 on pass and 1 on any failure.
  It honours `SMOKE_TIMEOUT` (seconds to wait for `healthy`, default `300`). It starts its own
  uniquely named container (no published ports) and removes it on exit via `trap`.

  by view name.

### Task 4: Workflow builds every version, smoke-tests, and publishes per tag

**Files:**
- Create: `.github/scripts/resolve-version.sh`, `.github/scripts/resolve-version_test.sh`
  (executable)
- Modify: `.github/workflows/docker-publish.yml`

**Interfaces:**
- Produces: `resolve-version.sh`. Reads env `REF_TYPE`, `REF_NAME`, `INPUT_VERSION` and
  `LATEST_VERSION`, and prints `GITHUB_OUTPUT` lines:
  - `version=<21|23|>`: empty when all versions are built.
  - `is_latest=<true|false>`.
  - `matrix=<compact JSON>`, shaped
    `{"include":[{"version":"23","platform":"linux/amd64","runner":"ubuntu-latest"},…]}`.

  Rules: a non-empty `INPUT_VERSION` builds that version; else a tag builds the tag's major; else
  every known version is built. Unknown or non-digit versions: print `::error::…` to stderr and exit 1.
  The version → platforms table lives only in this script.
- Consumes: `smoke-test.sh IMAGE` (Task 3), build arg `ORACLE_MAJOR` (Task 2),
  `test_convert_data.py` (Task 1).

- [ ] **Step 1: Write `resolve-version_test.sh`**, table-driven, using `jq` to check the matrix:
  - tag `v21.0.0` → `version=21`, `is_latest=false`, one entry (`linux/amd64`, `ubuntu-latest`)
  - tag `v23.0.8` → `version=23`, `is_latest=true`, two entries
  - branch `master`, no input → `version=` (empty), three entries
  - input `21` on a branch → one entry, version 21
  - tag `v22.0.0` → exit 1; input `22` → exit 1; input `21;rm -rf /` → exit 1

- [ ] **Step 2: Run it and confirm it fails**

  Run: `bash .github/scripts/resolve-version_test.sh`
  Expected: fails (script missing).

- [ ] **Step 3: Write `resolve-version.sh`.** Then run the test again. Expected: all cases pass.

- [ ] **Step 4: Rework `docker-publish.yml`:**
  - `env`: add `LATEST_VERSION: "23"`. Set `IS_RELEASE` to
    `${{ github.event_name == 'push' && startsWith(github.ref, 'refs/tags/v') }}`.
  - `workflow_dispatch.inputs.oracle_version`: string, default `""`, described as "Oracle major to
    build (21 or 23; blank = all). Smoke test only, never publishes."
  - New `setup` job on `ubuntu-latest`:
    - checkout
    - run `python3 -I -m unittest -v test_convert_data` and `bash .github/scripts/resolve-version_test.sh`
    - run `resolve-version.sh >> "$GITHUB_OUTPUT"`, passing `github.ref_type`, `github.ref_name`,
      `inputs.oracle_version` and `LATEST_VERSION` through `env:` (never interpolated into `run:`)
    - outputs `version`, `is_latest` and `matrix`
  - `build`:
    - `needs: setup`, `strategy.matrix: ${{ fromJSON(needs.setup.outputs.matrix) }}`, and
      `name: build (${{ matrix.version }}, ${{ matrix.platform }})`
    - `PLATFORM_PAIR` becomes `${version}-${platform with / → -}` (cache scope and digest
      artifact name)
    - steps, in order:
      1. Build with `load: true`, tag `sakila-ci:${{ matrix.version }}`, `build-args:
         ORACLE_MAJOR=${{ matrix.version }}`, and the gha cache (this replaces "Build (validate
         only)" and runs on every event)
      2. `./smoke-test.sh sakila-ci:${{ matrix.version }}`
      3. The existing "Build and push by digest", with the same `build-args`, still gated on
         `IS_RELEASE`
  - `merge`:
    - `if: ${{ needs.setup.outputs.version != '' && github.event_name == 'push' && startsWith(github.ref, 'refs/tags/v') }}`
    - `needs: [setup, build]`
    - metadata-action uses `flavor: latest=false` and tags
      `type=semver,pattern={{major}}` plus
      `type=raw,value=latest,enable=${{ needs.setup.outputs.is_latest == 'true' }}`
    - Replace the comment block about `flavor.latest=auto` to say why `:latest` is now explicit. The
      rest of the job is unchanged.
